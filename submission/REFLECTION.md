# Reflection — Small-file problem

Anti-pattern dễ gặp nhất là **small-file problem**. Log LLM hoặc sự kiện có thể được ghi liên tục theo các micro-batch nhỏ; lúc đầu pipeline vẫn chạy nên dễ chỉ nhìn số dòng mà bỏ qua số file. Tuy nhiên, nhiều file nhỏ làm query tốn thời gian mở file và đọc metadata, giảm hiệu quả file skipping, đồng thời làm chi phí compaction tăng. NB2 cho thấy compaction kết hợp Z-order giảm số file và giúp point query bỏ qua phần lớn file không liên quan. NB6 cho thấy đây không chỉ là vấn đề tốc độ: số lượng object lớn còn làm maintenance đắt hơn. Để phòng tránh, em sẽ theo dõi số lượng và kích thước file theo partition, điều chỉnh khoảng thời gian/batch size của writer, chạy compaction theo lịch, và clustering các cột được lọc thường xuyên. Như vậy, em xử lý nguyên nhân tạo file nhỏ thay vì chỉ chờ bảng chậm rồi mới dọn dẹp.
