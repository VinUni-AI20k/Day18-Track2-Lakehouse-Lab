# Reflection — Lakehouse Anti-Pattern

Em dễ mắc nhất anti-pattern **coi maintenance là việc làm sau**. Khi ingest LLM observability hoặc agent trace theo micro-batch, từng lần ghi đều đúng nhưng nhanh chóng tạo small files, log dài và metadata phình to. Nếu chỉ nhìn số dòng hoặc dashboard latency ở thời điểm hiện tại, em có thể bỏ qua chi phí request trên object storage, thời gian scan planning và rác từ job thất bại. NB2 và NB6 cho thấy đây không phải tối ưu hoá tùy chọn: compaction làm giảm file, Z-order giúp file skipping, còn expiry phải đi cùng orphan sweep. Đặc biệt, VACUUM không tự thấy file chưa từng được commit; giả định ngược lại sẽ để lại chi phí và rủi ro compliance. Vì vậy, nhóm sẽ đặt compaction, clustering, expiry, orphan removal và checkpointing thành job có lịch chạy, metric trước/sau và cảnh báo theo file count thay vì đợi truy vấn chậm mới xử lý.
